# Harbour Jackpot – Coded Landing Page

**TEST 2 – CODED LANDING PAGE**

## 1. Project Overview

Harbour Jackpot is a responsive, single-page marketing site for a weekly jackpot draw run by the fictional operator **Harbour Play**. It was coded from a Figma design with a mobile reference at **390px** and a desktop reference at **1440px**.

The site is plain static files (HTML, CSS, JavaScript and one JSON file) with no framework and no build step. All editable text and numbers are in **`data.json`**, which `js/main.js` reads when the page loads and uses to render every section.

> **Status:** not deployed, and the Git repository has no remote. Some content is unverified and marked as a placeholder in `data.json` (see [Editable Content](#7-editable-content-jackpot-draw-date-results-and-faq)).

## 2. Project Features

| Section | What it does |
|---|---|
| **Header** | Logo, five in-page links (Home, How to Play, Prizes, Results, FAQ), language label and "Buy Ticket" button. Below 1280px it becomes a burger menu that toggles `aria-expanded`, closes with **Esc** (returning focus to the button) and closes when a link is chosen. |
| **Hero** | Title, jackpot amount (gold gradient), ticket price and draw time, CTA and "18+" line over a captain illustration. Separate mobile and desktop artwork, served as WebP with a PNG fallback. |
| **Countdown** | Live days / hours / minutes / seconds to the next draw, updated every second and time-zone aware (Europe/Malta by default, daylight saving included). Shown twice: below the hero and above the footer. |
| **How to Play** | Three step cards. On hover, or tap on touch screens, the border turns solid yellow, the step number turns yellow and the blue tint over the artwork fades out. |
| **Prize tiers** | Four prize cards with the same hover/tap treatment. |
| **Latest results** | Draw date, draw number, five winning-number balls, winner count, and a "Next draw" card whose date is calculated automatically. |
| **FAQ** | Accordion. Gradient border by default, yellow border on hover, and a yellow border with `#000833` background while open. |
| **Footer** | Contact details, link groups (accordions on mobile), social icons, payment logos, copyright, language/currency/accessibility labels. |
| **Buttons** | Yellow CTAs turn white with a yellow outline on mouse hover and keyboard focus (fading over 0.28s). |
| **Content** | All copy and figures come from `data.json`. Tokens such as `{jackpot}` and `{drawTime}` let one value update every place it appears. |

## 3. Technologies Used

| Technology | Where it is used |
|---|---|
| **HTML5** | `index.html`: page shell with `<head>`, skip link and the `#app` mount point. Sections are generated by JavaScript. |
| **CSS3** | `css/main.css`: mobile-first styles; desktop layout from 1280px plus refinements for 320–1279px and 1280–1439px. Uses custom properties, Flexbox, Grid, `clamp()`/`min()`, `@font-face`, `@property`, `:has()`, `:focus-visible` and `prefers-reduced-motion` / `hover` / `pointer` media queries. |
| **JavaScript (ES module)** | `js/main.js`: `fetch()` of `data.json`, template rendering, token replacement, countdown (`Intl.DateTimeFormat`), FAQ, mobile menu, footer accordions and touch tap states. No libraries or dependencies. |
| **JSON** | `data.json`: all editable content. |
| **Web fonts (WOFF2, self-hosted)** | Roboto (variable) and Ryosa Ocean Black, in `assets/fonts/`. |
| **Images** | SVG icons; PNG artwork and logos; WebP versions of the two hero images. |
| **Netlify config** | `netlify.toml`: publish folder plus cache and security headers. |
| **Helper scripts (optional)** | Ruby, Node.js and Python scripts in `scripts/` for local serving and checks. The website itself does not need them. |

There are **no npm dependencies**: `package.json` only defines script shortcuts.

## 6. How to Run the Project

From the project folder, run **one** of these, then open **http://localhost:5173**:

```bash
ruby scripts/serve.rb
```

```bash
python3 -m http.server 5173
```

```bash
node scripts/serve.mjs
```

- The Ruby and Node servers accept another port as an argument (for example `ruby scripts/serve.rb 8080`) and send `Cache-Control: no-store`, so a refresh always shows your latest edits. With Python's server, use a hard refresh (`Cmd+Shift+R`).
- If npm is available, `npm start` runs the Node server and `npm run start:ruby` runs the Ruby server.
- Stop any server with `Ctrl+C`.

## 7. Editable Content (Jackpot, Draw Date, Results and FAQ)

Edit **`data.json`** only, save, and refresh the page. Do not edit the HTML or JavaScript for content changes. Keep the file valid JSON (double quotes, commas between items, no trailing commas), then check it:

```bash
python3 scripts/check.py
```

Keys starting with `_` (for example `_note`) are editor notes and are never displayed.

### Tokens

Any text can use these tokens, which are filled in automatically:

| Token | Source | Current value |
|---|---|---|
| `{jackpot}` | `jackpot.amount` | €1,000,000 |
| `{ticketPrice}` | `jackpot.ticketPrice` | €3 |
| `{drawDay}` / `{drawDayUpper}` | `draw.weekday` | Saturday / SATURDAY |
| `{drawTime}` | `draw.time` | 21:00 |

### Jackpot

```json
"jackpot": { "amount": "€1,000,000", "ticketPrice": "€3" }
```

`amount` appears in the hero, the Jackpot prize card and the browser tab title. `ticketPrice` appears in the hero tagline, step 2 and the meta description.

### Draw date and countdown

```json
"draw": { "timezone": "Europe/Malta", "weekday": 6, "time": "21:00", "nextDrawOverride": null }
```

- `weekday`: 0 = Sunday … 6 = Saturday. `time`: 24-hour `"HH:MM"` in `timezone`.
- The countdown and the "Next draw" date always target the next weekly draw. Changing the day or time also updates the hero tagline, both countdown subtitles and step 3.
- For a one-off draw, set `"nextDrawOverride": "2026-12-24T21:00:00+01:00"` (ISO date-time with offset). After that moment passes the weekly schedule resumes; set it back to `null` afterwards.

### Latest results

```json
"latestResults": {
  "drawDate": "Saturday, 14 Nov 2026",
  "drawNumber": "Draw #024",
  "numbers": [64, 19, 10, 11, 20],
  "winners": "5",
  "placeholder": true
}
```

Update these after each official draw and remove `"placeholder": true` once the values are real. **The current values are sample data from the design, not real results.**

### FAQ

```json
"faq": { "items": [ { "question": "…", "answer": "…", "open": true } ] }
```

Add, remove or reorder items freely. `"open": true` shows an item expanded on load.

### Other blocks

`site` (tab title, meta description), `cta` (all "Buy Ticket" buttons), `navigation`, `hero`, `countdown` (labels), `howToPlay`, `prizes` (four tiers; the artwork supports exactly four) and `footer`.

### Placeholders to replace before launch

`python3 scripts/check.py` lists every entry marked `"placeholder": true` (17 at the time of writing):

- `cta.href`: "Buy Ticket" has no purchase page (`"#"`).
- `latestResults` (sample results) and its "View All Results" link.
- All six FAQ answers.
- Footer links with no destination: Terms & Conditions, Privacy Policy, Safer Gambling, Set Your Limits, Get Support, and the three social links.

Also unconfirmed: the contact email, phone number and prize amounts come from the design, and the Prize tiers and Latest results subtitles repeat an unfinished sentence from the design.

## 8. Responsive Design (390px and 1440px)

The two Figma references are **390px** (mobile) and **1440px** (desktop). The layout switches from the mobile to the desktop structure at **1280px**.

| Range | Behaviour |
|---|---|
| **320–389px** | Mobile layout. The How to Play text column narrows and cards may grow taller instead of overlapping the art; result balls shrink but stay round. |
| **390–599px** | Mobile layout as designed (350px content column). From 420px the hero grows (capped at 700px) so the captain stays below the text. |
| **600–1279px** | Content column widens up to 704px; prize cards sit four in a row from 768px. |
| **1280–1439px** | Desktop layout. Step cards, the results card and footer columns scale down to fit. |
| **1440px and wider** | Desktop layout as designed; content stays centred at 1344px. |

**Verified on 18 Nov 2026** (Chromium with device emulation) at 320, 375, 390, 430, 768, 1024, 1280, 1366, 1440 and 1920px:

- no horizontal scrolling or clipped content;
- no distorted images and no broken images;
- interactions work: mobile menu, FAQ, footer accordions and countdown;
- no console errors;
- at 390px, 1440px and 1920px, every element sits in the same position as before the responsive refinements were added (391 elements compared).

The only remaining overlap is step 2's text touching its artwork by 5–13px, which matches the Figma design.

The later hero changes (WebP images, text scrim, 700px height cap) were re-checked at 390px and 1440px only: the correct WebP file loads at each width, with no horizontal scrolling, no broken images and no console errors.

## 9. Accessibility (WCAG 2.2 AA)

### Implemented and verified

| Area | Result |
|---|---|
| Structure | One `h1`; `header`, `nav`, `main` and `footer` landmarks; sections labelled by their headings; "Skip to main content" link. |
| Keyboard (2.1.1) | Logical Tab order, tested at 320px and 390px. FAQ opens with Enter and closes with Space. The mobile menu closes with Esc and returns focus to the button. |
| Focus visible (2.4.7) | Every link and button shows a 3px `#FFD600` outline; yellow CTAs also turn white. |
| Contrast (1.4.3) | Main text/background pairs pass AA. Lowest measured was light text on hero blue (5.96:1); body text on navy 19.9:1; CTA text on yellow 12.9:1; CTA hover text on white about 18:1. |
| Target size (2.5.8) | Targets are ≥ 24×24px or pass the spacing exception (desktop footer links 36px apart; header logo 71px from the nearest target). Mobile menu items are at least 30px. |
| FAQ semantics | Buttons with `aria-expanded` / `aria-controls`; answers are `role="region"` labelled by their question. |
| Countdown (4.1.3) | `role="timer"` with a label; screen readers get a once-a-minute summary instead of per-second updates. |
| Images | Content images have descriptive `alt` text, including payment logo names. Decorative images use `alt=""` and `aria-hidden`. |
| Motion | All CSS transitions are disabled under `prefers-reduced-motion: reduce`. Hover-only CTA styling is limited to `(hover: hover) and (pointer: fine)` so taps don't stick. |

The hero adds a navy scrim behind its text below 1280px. Its CSS comment records the 14px legal line improving from about 3.3–4.1:1 to at least 5.4:1; that figure has not been re-measured independently.

### Not yet tested

- Screen readers: VoiceOver, NVDA and JAWS.
- Real devices: iOS Safari, Android Chrome.
- Desktop Safari and Firefox.
- 200% text zoom and 400% reflow (1.4.4, 1.4.10).
- Text spacing (1.4.12).
- Automated audits with Lighthouse or axe.

## 10. Performance Optimisation

| Optimisation | Detail |
|---|---|
| No frameworks or third-party scripts | One CSS file (~29 KB) and one JS file (~16 KB), unminified, plus `data.json` (~7 KB). |
| Self-hosted fonts | Two WOFF2 files (~92 KB total) with `font-display: swap`. |
| Oversized images resized | `step-1.png`, `step-2.png` and `prize-sprite.png` were Figma exports at 4096 × 4096px (21.9 MB together). They were resized with macOS `sips` to 600, 700 and 1470px (about 2× their largest display size; 1.7 MB together). A pixel comparison at 1440px showed an average difference under 1%. |
| WebP hero images | `hero-desktop.webp` (68 KB) and `hero-mobile.webp` (59 KB) replace the 1.0 MB and 0.8 MB PNGs in supporting browsers; the PNGs remain as a fallback. The hero image has `fetchpriority="high"` and explicit dimensions. |
| Art direction | `<picture>` serves separate mobile and desktop hero, logo and fade images. |
| Lazy loading | Step artwork, prize artwork and payment logos use `loading="lazy"` and `decoding="async"`. |
| Caching | `netlify.toml` sets `no-cache` on `data.json` and a 7-day cache on `assets/*`. |

**Measured page weight** (all files loaded, Chromium, 18 Nov 2026): about **2.15 MB at 390px** and **2.11 MB at 1440px**, down from about 24 MB before the image work. The largest remaining file is `prize-sprite.png` (1.1 MB).

> **Caution:** `scripts/fetch-assets.mjs` (`npm run assets`) re-downloads all 45 Figma exports listed in `scripts/assets.json`, including the 4096px originals of the three resized images. It never runs automatically, and it only works while the Figma links are valid (about 7 days from the 17 Nov 2026 export). If you run it, resize again:
>
> ```bash
> sips -Z 600 assets/img/step-1.png
> ```
> ```bash
> sips -Z 700 assets/img/step-2.png
> ```
> ```bash
> sips -Z 1470 assets/img/prize-sprite.png
> ```

## 12. Build and Deployment Instructions

### Build

There is no build step; the folder is deployed as-is. Before each deployment, run:

```bash
python3 scripts/check.py
```

It verifies that:

- `data.json` is valid and has every required block;
- every referenced image, icon and font exists (PNG, SVG, WebP and WOFF2);
- no `localhost`, `file://` or `/Users/…` paths are used;
- every in-page `#link` points to a section on the page.

It also lists placeholders as warnings, and exits with an error if anything is broken. All paths are relative, so the site works at a domain root or in a sub-folder.

### Deploy to Netlify

`netlify.toml` already sets the publish directory to the repository root (`.`) with no build command.

**Option A – Netlify Drop (no Git or tools needed)**

1. Run `python3 scripts/check.py`.
2. Open <https://app.netlify.com/drop> and sign in.
3. Drag the `harbour-jackpot` folder onto the page; Netlify returns a `*.netlify.app` URL.
4. To update later: **Deploys** → drag the folder again.

**Option B – Netlify with GitHub (automatic deploys)**

1. Push the repository to GitHub (see [Git Repository](#13-git-repository)).
2. In Netlify: **Add new site → Import an existing project → GitHub**, then select the repository.
3. Branch: `main`. Build command: leave empty. Publish directory: `.`
4. Click **Deploy**. Every push to `main` then redeploys automatically; earlier deploys can be restored from **Deploys**.

**Option C – Netlify CLI (requires Node.js)**

```bash
npx netlify-cli deploy --dir . --prod
```

The `.claude/` folder is a local editor configuration; it is harmless if deployed, but you can exclude it when using Netlify Drop.
